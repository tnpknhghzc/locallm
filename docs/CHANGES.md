# Что изменено относительно исходного репозитория

Исходный код переписан; проблемы, из-за которых «нормально и быстро» не получалось:

| Было | Стало |
|---|---|
| Модели и llama.cpp нужно докачивать вручную; пустой submodule `llama.cpp` | Модели вшиваются в бинарник (`pack`), llama.cpp собирается `make deps` / CI, пользователь не делает ничего |
| Эмбеддинги `all-MiniLM-L6-v2` — только английский | Мультиязычные модели; размерность не зашита (было 384) |
| Новый контекст llama на каждый фрагмент при индексации | Один контекст, пакетные эмбеддинги, чекпоинты на диск, возобновление |
| Поиск перебором по SQLite с самописной пузырьковой сортировкой | Плоский индекс в памяти + top-k по куче (≈10 мс на 6 тыс. фрагментов) |
| Только PDF | PDF, DOCX, ODT, EPUB, FB2, RTF, HTML, TXT, MD |
| Нет чистки PDF | Убираются колонтитулы/номера страниц, склеиваются переносы и строки абзацев |
| Чанки по страницам | Дерево разделов (закладки/заголовки) + предложение-ориентированные фрагменты с перекрытием |
| Только векторный поиск | Гибрид BM25 (русский стеммер) + векторы + RRF + учёт «глава N» + центроиды разделов |
| Промпт мог не влезть в контекст | Подгонка по реальному числу токенов (ошибка «prompt too long» воспроизводилась на тесте) |
| Ждать индексацию всей книги | Книга отвечает сразу (BM25), векторы достраиваются в фоне |
| `-march=native` в сборке | Переносимые флаги AVX2; без libgomp; libstdc++ статически |
| Нет API/сессий | Go-пакет `pkg/locallm`, чаты на диске, сводки разделов, защищённый `serve` |

Найдено при проверке на реальных данных: `go-fitz` возвращает номер страницы закладки 0-based (в URI — 1-based).
