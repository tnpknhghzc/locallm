# Архитектура

```
файл ──► extract ──► chunk ──► store (tree.json.gz, vectors.bin, chats/, summaries.json)
         │            │
         │            └─ дерево: разделы (по закладкам/заголовкам) → фрагменты ~1000 симв., перекрытие 160
         └─ PDF(MuPDF) / DOCX / ODT / EPUB / FB2 / RTF / HTML / TXT → «страницы» + заголовки

вопрос ──► rag.Retriever ──► Answerer ──► llm (llama.cpp в процессе) ──► ответ + источники
           BM25 (стеммер RU/EN)  ┐
           векторы (flat cosine) ┴─► RRF ─► бонус разделам-центроидам ─► «глава N» сужает поиск
                                            ─► слияние соседних фрагментов ─► бюджет токенов
```

**«Помнить всю книгу».** Модель никогда не видит книгу целиком. На каждый вопрос берутся 5–10 лучших
фрагментов (≈2000 токенов) с указанием страницы и главы; промпт подгоняется под окно контекста по
реальному числу токенов (сначала отбрасываются наименее релевантные фрагменты, затем история).
История чата хранится на диске; короткие уточнения («а подробнее?») дополняются предыдущим вопросом.

**Иерархия.** Дерево разделов строится из закладок PDF, стилей Heading (DOCX/ODT), `h1–h6` (EPUB),
вложенных `section` (FB2), `#` (Markdown); если заголовков нет — по эвристике «Глава N / Chapter N»,
а иначе окнами по 20 страниц. Центроиды разделов (среднее векторов потомков) дают второй уровень поиска.

**Почему нет SQLite/HNSW.** 1500 страниц ≈ 5–10 тыс. векторов; полный перебор — около 10 мс.
Векторы пишутся append-only: индексацию можно прервать и продолжить, ничего не теряется.

**Один процесс, один контекст.** LLM и эмбеддер загружаются один раз (mmap); LLM — лениво.
Контекст LLM переиспользуется между вопросами (prefix-cache llama.cpp). Эмбеддинги считаются пакетами.

**Один файл.** `locallm pack` дописывает GGUF-файлы в хвост исполняемого файла
(`[exe][файлы][оглавление][длина][LLMPAYL1]`); при запуске они распаковываются в папку данных (один раз).
Это обходит лимиты Go на встраиваемые данные (>2 ГБ).

**Поиск моделей:** `-models` → `$LOCALLM_MODELS` → `./models` рядом с exe → рядом с exe → папка данных.
LLM выбирается по RAM (≤ 60% на модель+KV) и профилю (`fast|balanced|quality`).

**Безопасность `serve`:** только loopback, Bearer-токен (файл `server.token`, 0600), проверка Host
(DNS rebinding) и Origin (по списку `-origins`), лимит тела запроса.
